01 / THE PREMISE

Models are useful.
Kernels are evidence.

Simulation gets you speed. gateflow gets you closer to the conditions your service actually has to survive: Linux namespaces, kernel sockets, link state, routing, and packet impairment enforced below your application.

A1Nothing faked

Real network namespaces and real UDP/TCP traffic — not a user-space model of them.

A2Isolation first

Each sandbox gets its own network view, so tests can exercise failure without touching the host.

A3Chaos at the link

Delay, jitter, loss, reordering, corruption, and duplication through kernel netem.

03 / TOPOLOGY

When one namespace
isn't enough.

Sandbox::paired() builds a second namespace owned by the same user namespace, then wires both ends with a real veth pair. No host bridge. No fixed sleep. A handshake confirms both links are up before either closure runs.

04 / DEFENSE IN DEPTH

Resource limits.
Syscall boundaries.

Hardening is explicit. Add cgroup v2 memory, process, and CPU limits, then install a seccomp-BPF profile after network setup and before the test body runs.

⌗

cgroup v2

Memory ceilings, process-count limits, and CPU quotas under a delegated hierarchy.

OPT-IN / DELEGATED ROOT
◇

seccomp-BPF

Blocks namespace changes, mount operations, ptrace, BPF, reboot, and namespace-bearing clone calls.
